# 跨网 gboy 大厅联机修复：WS 服务器隧道回落

## Context

gboy.top 大厅联机的数据通路 = WS 信令 + 服务器分配的 **KCP/UDP 中继节点**，而该中继节点在服务端是死的（UDP 全静默，PROTOCOL.md §10/§11 多轮验证）。同网联机走局域网直连不受影响；**跨网络只能依赖中继，因此必挂**（表现："中继还没有回应"）。

修复：当 KCP 中继不可达时，**自动回落到 gboy.top 的 WS 信令通道转发游戏帧**（`send_message` 广播信道已被验证可送达房间成员——现有 gboy_node 节点广播就走的它）。双方都连着 `wss://gboy.top:23459`，WS 是出站 TCP，无 NAT/UDP 限制，跨网天然可用。KCP 优先尝试 12 秒（保留将来官方修好中继后的低延迟路径与真 GBoy 互通），失败即切隧道。

## 隧道协议（复用 send_message 信道，房间标记过滤）

- 就绪标记（双方进入数据阶段后每 2s 发）：`{"gboy_ws":"hello","room":"<房号>"}`
- 收到对方 hello → 回一次 `{"gboy_ws":"accept","room":"<房号>"}`，双方进入隧道模式
- 数据帧：`{"gboy_ws":"f","room":"<房号>","d":"<GBoy 帧整帧 base64>"}`（KEYS 帧约 14 字节；沿用现有"按键变化才发+500ms 心跳"节流，实际 ~2-5 条/秒）
- WS 有序可靠，无需确认/重传；帧编解码直接复用 `GBoyFrames`

## Android 改动

1. **`android/app/src/main/java/io/mgba/android/GBoyCloudLink.java`**（主要）
   - 抽最小传输接口 `Link { send(byte[]); byte[] recv(long); boolean isClosed(); void close(); }`，`KcpChannel` 实现之（签名已完全吻合）；`handshake()/expect()/serve()` 改收 `Link`
   - 新增内部类 `WsLink implements Link`：包住现有 `GbCloud.Session` + `GBoyFrames.Reader`，实现 hello/accept 应答、base64 帧收发、按 room 标记过滤
   - `connectRelay()`：现有 `startRelayLink` KCP 重试循环加 12s 总窗（新常量），窗内每秒顺带排空 WS + 发 hello；窗口耗尽或节点缺失 → 切 `WsLink`：隧道等待（互发 hello/accept）→ 房主多发一帧 `TYPE_READY(2)`（解决现有 `handshake()` 双方互等 READY 的死锁）→ 复用现有 `sendRegister`+`handshake()` → `serve()`
   - **单读者纪律**：`startNodeAdvertiser` 线程改为只发不收（删除其 `sig.recv`），工作线程成为 WS 唯一读者（否则隧道帧会被广告线程吞掉）
   - 状态文案补充"中继不可达，已切换服务器隧道模式"
2. **`GbCloud.java`**：`API/WS_HOST/WS_PORT` 增加包内可变覆盖（默认值不变）——供本地 mock 服务器测试
3. **`EmulatorActivity.java`**：`action.CLOUD` 广播新增可选 extra `ws`（`host:port`），照抄现有 action.KEYS 模式注册
4. **`res/values/strings.xml`**：`link_cloud_help` 补充跨网自动隧道说明

## PC 改动（Qt，镜像同一套）

- **`src/platform/qt/CloudLink.h/.cpp`**：`ILink` 抽象（KcpChannel 实现）+ `WsLink` 类 + 同样的 12s 回落流程；PC 端本来就是工作线程单读者（`pollSignaling` 在 serve 循环内），改动更小
- **`src/platform/qt/GbCloud.h/.cpp`**：`wsHost()/wsPort()/api()` 增加可覆盖 setter
- **`src/platform/qt/KcpChannel.h`**：挂上 ILink
- **`src/platform/qt/test/gboylink_test.cpp`**：cloud2 模式支持从环境变量/参数读 WS 地址覆盖
