## 二、游戏内联机（D:/gen8/rom.gba）握手卡死 —— 根因链已基本定位

**现象**：大竞技场 → 单打对战 → 存档 → 房间内出现「2P连接」「与玩家2开始连接。」，主机按住 A 后约 10 秒，两端弹「对不起，连接发生了错误…」。

**已确认的事实**（PEEK 探针）：
- SIO 隧道**本身是健康的**：`SIO multi ok=40320、to=0（零超时）、m0=B9A0 m1=B9A0` 双向握手字交换正常，主从 Slot（SIOCNT SD/Id 位）正确
- 主机 `gLink.isMaster=8`、`playerCount=2`，但 **state 永远停在 `LINK_STATE_HANDSHAKE(2)`**，`SIOMULTI0` 恒为 `B9A0`（SLAVE_HANDSHAKE），**从未发出 `MASTER_HANDSHAKE(0x8FFF)`**

**代码级根因**（`D:/gen8/src/link.c`）：
- `DoHandshake()` (2250)：只有 `gLink.handshakeAsMaster==TRUE` 才把 `0x8FFF` 写进 `REG_SIOMLT_SEND`；返回 TRUE 需 `tempRecvBuffer[0]==MASTER_HANDSHAKE`
- `handshakeAsMaster=TRUE` **唯一**入口是 `LinkMain1` (1979-1984) 的 `LINK_STATE_HANDSHAKE` 分支，条件 `*shouldAdvanceLinkState==1 && isMaster==LINK_MASTER && playerCount>1`
- `LinkMain1` 每帧末尾 `*shouldAdvanceLinkState = 0` (2000) → **该旗标只存在一帧，降采样 PEEK 必然测不到**（这是之前误判「旗标从未置位」的测量陷阱）
- 置位来源只有：`Task_TriggerHandshake`（OpenLink 后 5 帧，会被 START1 分支吃掉，只推进到 HANDSHAKE）、`CheckShouldAdvanceLinkState()` (1146)
- 本 ROM 大竞技场走 cable_club 的 `Task_Linkup*` 链：
  - `Task_LinkupAwaitConnection` (229)：主机 → `Task_LinkupConfirmWhenReady`，**从机 → `Task_LinkupExchangeDataWithLeader`（从机根本不需要那次 kick）**
  - `Task_LinkupAwaitConfirmation` (268)：`JOY_NEW(A)` + 人数够 → `SaveLinkPlayers` + 显示 `gText_ConfirmStartLinkWithXPlayers`=「与玩家2开始连接。」
  - `Task_LinkupTryConfirmation` (293)：**必须消息框已隐藏** + `JOY_HELD(A)` → `CheckShouldAdvanceLinkState()`
  - `Task_LinkupConfirm` (321)：`if (GetLinkPlayerCount_2() != GetSavedPlayerCount()) → Task_LinkupConnectionError` ← **这就是「连接发生了错误」**
  - `GetLinkPlayerDataExchangeStatusTimed` (825)：`++gLinkTimeOutCounter > 600`（10 秒）→ `EXCHANGE_TIMED_OUT`；`GetLinkPlayerCount()==0` 也会 `CloseLink`
- 其他 `CheckShouldAdvanceLinkState` 调用点：`battle_controllers.c:777`（`Task_HandleSendLinkBuffersData` case2）、`cable_club.c:1305`（`sub_80B3AF8` case2，大竞技场备用路径）

**所以失败最可能是输入侧**：确认框没关掉 / A 没真正被按住 → 主机拿不到那次 kick → 10 秒超时报错。次要可能是拿到 kick 后块交换（block transfer）阶段才失败（未验证）。

## 五、不变速（WSOLA）电音修复

**现象**：倍速勾选「不变速」后音乐有「电音」（金属/振铃感）。

**根因**：`wsolaGenerate` 用原始 Hann 窗做 overlap-add。Hann 窗仅在 50% 合成重叠（Hs=N/2）时 OLA 求和才为常量；不变速 Hs=N/(2·stretch) 远小于 N/2（s=4 时重叠 87.5%），原始 Hann 的 OLA 和随帧周期起伏 → 幅度调制 → 电音。

**修复**：在 `initAudioHold` 里把 Hann 窗按自身 OLA 包络预归一化（`wsolaWinF[i] = Hann[i] / COLA[i]`，COLA 以合成跳 Hs2 计算）。这样 OLA 处处增益恒为 1，彻底消除幅度起伏，同时交叉淡化形状不变 → 接缝连续性保持（抖动与修复前一致）。运行时 OLA 不再做逐样本除法（与旧 int16 路径同形，仅累加）。

**验证**：`mgba_mobile_test` 的 `testAudioConstPitchRealtime` 全部通过 —— 不变速 4× 输出 516.4Hz（1.01×，音高正确）、jitter 0.057（< shredded 0.101 的 0.7 倍）、整曲连续不跳段。注意 `mgba_mobile_test` 有 7 个既有 FAIL 属 pace 估算器，与本修复无关。

**产物**：重新编译 debug(`app-debug.apk` 11.6MB) 与 release(`app-release.apk` 7.5MB)，路径 `android/app/build/outputs/apk/{debug,release}/`。

**关键坑（再遇到别踩）**：
- phase 搜索的参考 `prev` 必须在**输入域**（acc 尾部，即加窗后的输入），不能取归一化后的输出（emit）——否则搜索在输入/输出两个不同波形间对齐，导致音高错乱（实测变成 1.9×）与抖动飙升。
- 参考窗长不能用重叠区整段（ref=N-Hs）：输入域参考若取自窗峰（高能量）会引入半周期歧义，实测音高翻倍（1.92×）。安全做法是 ref=Hs（近零窗边），锁零交叉，音高正确。
- 真机倍速听感仍需手动确认：进游戏→点「1倍」→勾「倍速声音」→勾「不变速」→选 4/16 倍。

## 六、GBoy 联机协议逆向（进行中）

**目标**：让 mGBA 安卓移植走 GBoy 官方房间服务器联机（与 GBoy 用户互通）。

**关键事实（已确认）**
- 包名 `com.game.boy`，壳 `com.game.boy.shell.ProxyApplication`；`classes.dex` 是「多 dex 拼接容器」：主 dex 9.6KB 仅壳，真实代码在随后 4 个内嵌 dex（切分偏移 0 / 9680 / 8089644 / 16201140 / 22780824）。
- **dex 指令段被加密**（dexdump 反汇编全是乱码指令、大量 `GLITCH: run-away instruction`），只有**字符串池是明文** → 静态反编译无用，只能靠字符串 + 黑盒探测。
- 宿主 x86_64 跑不了 `gboy_arm`（ARM64 系统镜像），所以**无法真机跑原 APK**，Frida 动态方案不可行。

**WS 协议（已破解部分）**
- 报文：JSON 文本帧 `{"action":"<snake_case>", ...}`。
- 已确认动作：`ping`(→`{"action":"pong","time":<秒>}`)、`create_game_room`、`join_room`、`leave_room`、`query_room`、`ready`、`invite_player`、`update_room_settings`。

## 七、异地联机（跨网络）打通方案

**结论**：不需要 GBoy 服务器。三条路，按推荐度：
1. **虚拟局域网（零服务器）**：两端装 Tailscale/ZeroTier → 用「局域网创建/加入」填 100.x 地址。
   `link_net.c` 的 `openListen()` 是 `INADDR_ANY`（已核实），VPN 网卡直接可用。
2. **公网中继 + 房间号**：`relay.py` 跑在有公网 IP 的机器（纯标准库），双方在「联机大厅」填 `ip:8766`，一边创建拿房间码，另一边加入。
   本机不留中继地址时会起**内嵌中继**（`RemoteLink.startEmbedded`，Java ServerSocket，同样绑所有网卡），但显示的是 LAN IP。
3. 家庭电脑 + 端口映射 / frp，等价于 2。

**已做的代码改动（2026-10-29）**
- `EmulatorActivity.java`：新增 `localIpv4List()/localIpv4Hint()/ipv4Rank()`，等待提示改为列出**全部**本机 IPv4（192.168 优先，Tailscale 100.x 次之），原来只报第一个，异地必然给错地址。
- `strings.xml`：新增 `link_waiting_multi`。
- `link_net.c`：新增 `PKT_PING/PKT_PONG`，`netLinkBarrier` 每 1s 发一次探针（走 IO 线程回声），`netLinkStatusText` 输出追加「· 延迟 Xms」。旧的 `rttMs=0` 时不追加，向后兼容。
- 验证：NDK clang 单编 `link_net.c` 0 warning；`gradlew :app:assembleDebug` 成功（25s）；APK 11.6MB。

**工具**
- `relay_probe.py`：异地连通性自检（TCP 握手计时 + 建房/加入/PEER + 双向 16 字节校验），对面在自己网络跑一条命令即可判定。
- `relay_test.py`：中继协议单测，15/15 通过。

**踩坑**：本机 8767 端口落在 Hyper-V 保留段（bind 报 WinError 10013），8766/8776 正常。VPS 部署时同理要确认端口没被占。

**延迟现实**：GBA 联机线是同步串行，两边必须在同一节拍交换同一个字，RTT 直接换成掉帧。`netLinkBarrier` 是每帧一次，估计帧周期 ≈ max(16.7ms, RTT/2)：RTT<33ms 满速，60ms 约 33fps，100ms 约 20fps。若实测掉速，下一步做「自适应上帧延迟」（barrier 允许落后 N 帧）或把中继放到离双方最近的机房。

## 十、不变速电音「真正」根因 + 切换复选框崩溃（2026-10-29 晚，覆盖第五节旧结论）

**第五节那套「Hann 按 OLA 包络预归一化」是误判，已回退。** 本次定位到真因：

### A. 电音真因：OLA 累加器尾部没清零，逐帧无限累加
`wsolaGenerate` 每帧 `memmove(acc, acc+Hs2, (W2-Hs2))` 左移后，**`acc[Hs2..W2)` 仍是旧值**，下一帧又往上 `+=` → 累加器把所有历史帧的尾段一直加进去，波形越滚越大、被 int16 截断 → 听感就是金属/电音，且 native 测出音高 1.93×、jitter 0.408。
修复：memmove 之后 `memset(acc + Hs2, 0, (W2-Hs2)*sizeof(float))`。这样每帧出样 = 当前帧头 + 上一帧尾，才是标准 OLA。
顺带把 Hann 窗分母从 `n2-1` 改回 `n2`（周期 Hann，50% 重叠严格 COLA）。
**验证（当前源码）**：`realtime 不变速 4x WSOLA: 241200/241200 frames, 512.0 Hz (1.00x), jitter 0.000`，三条断言全过。之前的 1.93×/0.408 消失。

### B. 崩溃真因：UI 线程 free 掉音频线程正在用的 WSOLA 缓冲（use-after-free）
速度菜单里「声音」「不变速」复选框的 `OnCheckedChangeListener` 在 **UI 线程** 跑 → `syncFastAudio` → `core.setAudioConstantPitch` → `initAudioHold`/`deinitAudioHold` → `free()/calloc()`；而「mGBA」模拟线程同时在 `pumpAudio → readAudioOut → wsolaGenerate` 里解引用同一批指针 → 段错误（崩）。
之前的 `initAudioHold` 还有个 bug：早退比较 `stretch - emu->wsolaStretch` 是同一个变量 → 永远相等 → 改倍速时从不重建（Ha 不更新）。
**修复**：WSOLA 缓冲区生命周期 **只归音频线程**。
- `mgbaMobileSetAudioConstantPitch` 改成只写 `wsolaStretch / wsolaClearPending / audioHoldOn` 三个标志，绝不碰缓冲。
- 新增 `wsolaConfigured` 字段：`initAudioHold`（仅在 `readAudioOut` 音频线程里调用）比较 `requested(wsolaStretch) vs wsolaConfigured`，变了才 deinit+重建 → 同时修好「改倍速不更新 Ha」。
- `readAudioOut` 里若 `wsolaClearPending`，在音频线程上清 `audioHold/wsolaIn` 并复位 `wsolaAnaPos` 后再跑 WSOLA。
- calloc 加 NULL 检查（失败则 deinit 并退回非拉伸路径，不崩）；`audioHoldInited` 提前置 true 便于失败时清理。
- 编译期 `netLinkWaitForPeer` 未定义链接错误：源码已改名为 `netLinkTakePeerWord`（`link_net.c` 有定义），首次 gradle 报错是 `.cxx` 里的**陈旧 .o**，重跑即好。
