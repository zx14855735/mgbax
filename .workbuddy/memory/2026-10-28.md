## 修复：连点B跑步卡死（mGBA Android 模拟器）

**根因**：专用于连发B的屏幕按钮（ControlsView 的 B连/连发键）通过 `publish→onKeysChanged→noteUserKeys→core.setKeys` 把 B 位脉冲进 `heldKeys`；同时 `noteUserKeys` 看到 B 被按住超过 `TURBO_ARM_MS` 又会去 arm 住手B自动连发（`armTurbo`→`core.setTurbo(B)` 设 `turboMask`，并 `publishKeys` 从 `heldKeys` 剥离 B）。结果是 B 同时被两个来源驱动。原生 `readLiveKeys` 里 `keys = frameKeys | held | latch`，`beginFrameKeys/applyTurbo` 在 turbo 关帧已正确撤下 B，但 `held` 仍带有连发按钮的 B 位 → 又被 OR 回去，B 每帧都被报成按下。宝可梦类游戏按住 B=跑步，于是角色一直跑停不下来（“跑步卡死”）。

**修复（两处）**：
1. `src/platform/mobile/mgba_mobile.c` `readLiveKeys`：在合并 `held`/`latch` 前先把 `turboMask` 对应位屏蔽掉，保证 turbo 键只由 `applyTurbo`/`turboMask` 每帧决策控制，关帧不会被 held 重新置位。这是根因修复。
2. `android/.../EmulatorActivity.java` `noteUserKeys`：当 B 的按下来自专用连发按钮（`controls.turboBPressed()`）时，不再 arm 住手B自动连发，避免两套 turbo 叠加。
3. `android/.../ControlsView.java`：新增 `turboBPressed()` 访问器，供上面的 guard 使用。

**补充回归测试（host 端，已落地）**：
- `src/platform/mobile/mobile_test.c` 新增 `testTurboBRom`：用真实 `D:/gen8/rom.gba` 跑 240 帧，模拟“连发B按钮 + 自动连发同时开”的场景（先 `mgbaMobileSetTurbo(B)` 再 `mgbaMobileSetKeys(B)` 脉冲），通过新增的探针 `mgbaMobileLastKeys()`（返回 `gba->keysActive`，即游戏实际读到的键状态）统计 B 被按下的帧数/连续按住最长帧数。
- `mgba_mobile.c` `readLiveKeys` 上方与 `mgba_mobile.h` 中新增 `mgbaMobileLastKeys`，仅测试/调试用。
- **测试结果（决定性）**：用 `build-mobile-test` 的 ninja 编出 `mgba_mobile_test.exe` 跑真实 rom.gba —— 带修复：`turboB 连点B: pressed=120 released=120 longestHeldRun=1`（B 只在 turbo 开帧按下，关帧必释放）；临时去掉 `& ~turbo` 掩码还原 bug：`pressed=240 released=0 longestHeldRun=240`（B 每帧都被钉死=卡死）。证明测试能抓到 bug，且修复有效。其余 3 个场景（连发键单独脉冲 / 按住B不松 / 松开即释放）两种版本都通过。全套其余失败均为既有的 audio-pace 估算器用例（与本次改动无关，6 个稳定失败）。

## 修复：方向键不显示（「普通模式」APK）

**现象**：用 APK 打开 rom.gba 后屏幕没有可用方向键，D-pad 被渲染成一个深蓝方块、上面写着「DPAD」文字（不是可按压的十字方向键）。

**根因**：`EmulatorActivity.skinStylePref()` 默认返回 `STYLE_HANDHELD`（掌机皮肤样式，字符串「掌机(竖屏 Pizza Boy 风/横屏 GBA 风)」）。该模式依赖皮肤 PNG 资源绘制按键；本构建里 D-pad 的皮肤图形未加载，回退成带文字标签「DPAD」的占位方块，无方向功能。用户要的「普通模式」= `STYLE_CLASSIC`（字符串「经典(半透明线条)」，矢量绘制，不依赖皮肤 PNG，D-pad 一定是正常十字）。

**修复（两处）**：
1. `android/app/src/main/java/io/mgba/android/EmulatorActivity.java` `skinStylePref()` 默认值 `STYLE_HANDHELD` → `STYLE_CLASSIC`（`getInt("skin_style", ControlsView.STYLE_CLASSIC)`）。
2. `android/app/src/main/java/io/mgba/android/ControlsView.java` 字段 `private int skinStyle = STYLE_HANDHELD` → `STYLE_CLASSIC`。
- 重新 `./gradlew :app:assembleDebug --offline`（仅 Java 改动，19s BUILD SUCCESSFUL，APK 14:34）。
- 模拟器上 `pm clear io.mgba.android` 重置偏好后打开 rom.gba，截图确认 D-pad 为正常十字、A/B/START/SELECT/L/R 全部正常显示。✅
- 注意：已安装过的旧 APK 会把 `skin_style=HANDHELD` 存进 SharedPreferences，改代码默认值对其不生效；需清除应用数据/重装，或在设置→按钮皮肤→皮肤样式里选「经典(半透明线条)」。

## 存档加载位置（与「读取存档异常」相关）

**关键事实**：mGBA Android 的电池存档目录由 `SaveLocation.prepare()` 决定——授权后（`MANAGE_EXTERNAL_STORAGE` 或旧版写权限）返回 `Environment.getExternalStorageDirectory()/mGBAx/saves`（即 `/sdcard/mGBAx/saves`）；无权限时退回 `getExternalFilesDir/saves` 或 `getFilesDir/saves`。**不是 ROM 同目录**。存档文件名 = ROM 基名 + `.sav`（本例 `rom.sav`）。
- 之前把 `rom.sav` 推到 `/sdcard/Download/`（ROM 目录）是放错位置，mGBA 找不到 → 游戏开新档，表现为「读取存档异常」。改放 `/sdcard/mGBAx/saves/rom.sav` 后，logcat 出现 `GBA save type forced to 3`（= FLASH 128KB，即 131072 字节 Flash 存档类型），无 Corrupt 报错，说明已正常加载。
- **待确认风险**：`D:/gen8/rom.sav` 实际为 131088 字节 = 128KB + 16 字节头部（前 16+ 字节为 0x00，非 mGBA 的 MBSC 魔数；本代码库 grep "MBSC" 为空，说明是较老版本、裸存档无头）。mGBA 裸存档加载（`GBASavedataInitFlash` 直接 `map(vf, flashSize)`）会取文件前 131072 字节当存档，即把那 16 字节零头当存档起始、漏掉末尾 16 字节真实数据 → 理论上可能让宝可梦这类靠校验和的存档整体偏移 16 字节、校验失败。尚未盲改用户存档（怕改错位置损坏）。若用户实测游戏里仍读不到正确进度，再生成「去掉前 16 字节」的干净 131072 字节副本（rom_clean.sav）给他试。
